# 开发日志

## 2026-11-15：足底滑移与落脚稳定性改进

**背景：** baseline 能完成绕杆路线，但存在足底滑动和接触抖动，需要补充步态质量约束。

### 已完成

- 修复摩擦随机化：地面优先级高于足部，原实现使随机化后的实际接触摩擦固定为 0.3；现让脚和地面同时采用采样值。
- 在原有 `reward_tuning.py` 中加入 foot slip 和近地向下落脚速度惩罚，初始权重分别为 **0.05、0.02**。仿真采样和世界模型想象共用原有 `tuned_reward()` 入口。
- 保留基础奖励公式；`Q1Robot` 增加足底点运动学计算，`reward()` 增加可选 `next_heads` 参数以复用运动学结果。新增 `foot_contact.py` 只负责测量阈值、验收条件和版本标识。
- 评估记录实际承重接触的滑移均速、RMS、超速比例和双脚承重时间。选模同时要求路线通过、滑移均速 ≤ **0.1 m/s**、超速比例 ≤ **20%**；超速定义为滑移速度 > 0.05 m/s。
- checkpoint 增加奖励配置与接触指标版本检查。旧 baseline 可回放和评估，但不能直接恢复到新的训练配置。

### 验证结果

- 首轮 **88 项测试通过**；奖励接入复核 **65 项通过**，两次覆盖范围重叠。每次均跳过 1 项可选资产检查，并排除 1 项会执行优化器更新的测试。
- 验证了实际摩擦、足底速度、奖励梯度和评估选模；两条训练路径开启足底项后的奖励差均等于 `dt × 两项惩罚之和`。
- 旧策略五个场景均保持路线成功，但全部未通过新滑移门槛。`nominal-01` 的滑移均速为 **0.17266 m/s**，超速比例为 **30.48%**；这只验证指标接入，不代表策略已改善。
- 数据、配置与 warmup 严格加载检查通过；检查时工具环境的 CUDA 不可见，正式训练前需在训练终端确认 `hardware.ready: true`。

### 后续

从登记的 warmup 初始化，先用 `--max-updates 1` 验证训练流程，再按现有 **2,000 次冻结 Actor 的 warmup + 500 次 Actor 更新**配置训练。根据路线与滑移指标比较结果，再决定是否调整奖励权重。

本次开发验证未启动训练或更新策略权重；尚未验证训练收益与实机迁移，也未处理 GUI 退出时的段错误。

详细说明见 [足底奖励与验收](foot-contact-rewards.md)，启动命令见 [杆间绕行训练说明](pole-weaving.md#预检查与训练)，验证记录见 verification.json（本地 `outputs/foot-contact-change-validation/verification.json`）。

## 2026-11-15：2100 推理视频观察与后续优化项

- 对象：`run-20261115-160417/checkpoint-002100.pt`，`nominal-01`，对应视频 `checkpoint-002100.webm`（约 86.88 秒）。本次检查全片分段抽帧及用户提供的推理日志。
- 当前路线表现稳定，5 次回放均完成路线、无摔倒或碰杆；滑移均速 0.09098 m/s，超速时间比例 16.83%，根部 XY RMSE 2.69 cm。相比此前 baseline 的同场景 CPU 评估，滑移均速下降 47.3%，超速比例从 30.48% 降至 16.83%，路线误差基本保持不变。这是整体改动后的结果，不能单独归因于某一项奖励。
- **用户要求记住的行为：机器人行走时偏好侧向抬起大臂。** 抽帧中可见上臂外展、肘部外撑、手靠腰侧，类似叉腰姿态；视频约 4～8 秒以及后续同路线阶段重复出现，属于后续优化项。本轮仅记录，不修改手臂奖励或策略。
- 后续先对照参考动作及肩关节轨迹，区分参考本身的姿态与策略额外外展，再讨论约束；目前未确认其是否承担平衡补偿，也未量化外展角度。优化时需同时复查现有步态稳定性。
- 5 次回放为固定条件下的重复，不代表随机扰动鲁棒性；左转场景仍有未通过的滑移指标，不能据此宣称所有场景或实机都已稳定。
