# V1 · B-2400

V1采用B实验的四段采样方式，选中 `B2200_2500/best.pt`（update=2400）。已独立归档到 `版本记录/V1/best.pt`，SHA-256：

```text

```

## 训练方式

- 源warmup初始化，种子20261103；课程warmup 2000次冻结Actor，随后开启Actor与物理随机化。
- 仅Actor采用四段轮换起点，段内按原回合种子随机；nominal每批覆盖四段，straight／left_turn／right_turn在两批内覆盖四段。
- 每批采集nominal 4回合，其余三个训练场景各2回合；Actor replay保留最近两批，每25次更新刷新。
- Actor基础学习率1e-5，世界模型／Critic为1e-4，保留原余弦调度；滑移／落脚／手臂权重0.05／0.02／0.05。
- 每25次评估，每50次保存编号快照；基础奖励、动作缩放、噪声、门控和正式门槛不变。

原始训练分三段：`B-stratified-to1000` → `B-stratified-from1000-to2200` → `B2200_2500`。最后一段运行到2500，选中其中2400。当前默认配置可直接新训练到2500，但因为恢复会重建RNG/replay，不应宣称单次不中断训练能逐位复现该模型。

原B配置 `experiments/reward-sampling/B.json` 原样保留。主线 `courses/pole-weaving/pole_task/config.json` 与B只差输出目录，默认输出仍在 `logs/q1-pole-weaving/`。配置省略采样字段时仍沿用旧uniform行为。

## 结果与限制

CPU、seed=20261103，nominal、eval、straight、left_turn、right_turn全部完成路线，无摔倒、碰杆，并通过原滑移均速≤0.10m/s、超速比例≤20%的门槛。完整结果见 [V1-evaluation.json](V1-evaluation.json)。

与原footflip-2100比较，五场景连续承重均速和再承重积分均下降，左转分别下降36.9%和54.0%；但不能解读为所有接触分项都改善。左转、直行总承重时间约少7%，直行按承重秒归一化的再承重积分略高2.1%；右转再承重次数92→106。相对B-2200，直行再承重积分增加13.6%。这仍是单种子固定仿真结果，尚未验证实机和扰动鲁棒性。

本地完整分析：`outputs/B-extension-cpu-review-20261116/报告.md`。2500后期退化，不用 `latest.pt` 替换本版的2400。

## 运行

从仓库根目录执行：

```bash
conda activate env_q1
python -m pole_task.play --checkpoint "版本记录/V1/best.pt" \
  --case nominal-01 --device cpu --gui --seed 20261103 --loops 1
python -m pole_task.evaluate --checkpoint "版本记录/V1/best.pt" \
  --device cpu --seed 20261103 --output outputs/V1-evaluation/evaluation.json
```

新训练使用默认配置和独立run名：

```bash
python -m pole_task.training --preflight-only
python -u -m pole_task.training --max-updates 2500 --run-name V1-new-run
```

如需恢复V1模型，必须使用原B配置，而非新版主线默认配置：

```bash
python -u -m pole_task.training \
  --config experiments/reward-sampling/B.json \
  --resume-checkpoint "版本记录/V1/best.pt" \
  --max-updates 2500 --run-name V1-resume2400-to2500
```

这是恢复入口示例，不建议因版本整理而重跑已知退化的2400→2500。旧主线模型使用 `experiments/reward-sampling/pre-V1-main.json`；A模型使用原A配置。恢复校验仍严格，不改写checkpoint身份或源配方。
