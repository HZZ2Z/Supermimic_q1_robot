# 训练程序流程

> 说明：训练代码根目录为 `courses/pole-weaving/pole_task/`。
> 入口 `python -m pole_task.training` 在 `training.py:712` 的 `main()` 中将控制权转交给 `source_training.py` 的 `main()`，因此本文行号均指真实执行路径。

## 流程总览

```text
main() ─▶ ① 预检（哈希 / 契约 / 硬件 / 试加载，全过才继续）
   ─▶ ② recipe（warmup 2000 + actor 500 两阶段）
   ─▶ ③ load_source_pole（从 7.7 warmup 继续，不从零开始）
   ─▶ ④ run_dir + PoleMotions（参考动作库）
   ─▶ ⑤ 采集 episode（环境步进、tuned_reward、撞杆/摔倒终止）
   ─▶ ⑥ for update:
         阶段切换 → 重新采集（随机化物理）
         fit_model × N → improve_policy(update_actor=阶段开关)
         评估边界 → source_acceptance → best.pt / latest.pt / patience
         预算 / patience / 冒烟限制 → stop_reason.json
   ─▶ ⑦ identity.json 回填（复现凭据闭环）
```

## 二、预检

**位置**：`preflight.py:30` — `preflight()`

训练前把所有"不可能条件"一次性排掉，任何失败都不产生 run 目录：

| # | 检查项 | 内容 |
|---|---|---|
| 1 | 来源清单 | `verify_source_manifest()` 校验 warmup checkpoint 存在 |

| 5 | 硬件 | CUDA 显存 ≥ `gpu_min_free_gb`、sm 架构在编译列表内 |
| 6 | 试加载 | `fork_rng` 保护下真加载一遍 warmup——哈希一致只证明字节相同，严格加载才证明可用 |

## 三、解析配方

**位置**：`source_training.py:467`

```python
recipe = resolve_source_recipe(config_path, project_root=root)
```

从 `data/source-configs/warmup-v10.toml` + `actor-v10-block7.toml` 读出两个 `SourceStage`（`source_recipe.py:266-267`）：

| 阶段 | `actor_updates_enabled` | `randomize` | 作用 |
|---|---|---|---|
| `warmup`（2000 更新） | **False** — 只练 world model + critic | False | 从 warmup checkpoint 出发重建想象模型 |
| `actor`（500 更新） | True | True | 在带随机化的新采集上更新策略 |

- `recipe.stage_for_update(update)` 按更新序号查阶段；
- 学习率按 `optimizer_rates(update)` 周期调度（250k 步周期衰减到 0.03 倍下限）。

## 六、采集 episode

**位置**：`source_training.py:579-591`（调度）→ `source_runtime.py:141` — `run_source_episode()`（环境真正被步进的地方）

```python
start_frame = 随机采样（训练时）
environment.reset(start_frame)
observation = robot.observation(state, context)      # 78 维
history     = 10 帧观测窗口                           # SOURCE_HISTORY_FRAMES
while not done:
    references = _reference_window(motions, clip, frame, 1..10)   # 未来 10 帧参考
    goal   = source_goal_features(robot, references, state)
    action = actor(history, goal)                    # 22 维，硬校验
    next_state, transition = environment.step(executed)
    reward = tuned_reward(robot, state, next_state, target, reward_action, ...)
    terminal = robot.terminated(...) or pole_collision            # 摔倒或撞杆
```

采集在**阶段切换时整批重做**（见下一节）：actor 阶段的物理带随机化，不能用 warmup 阶段的确定性转移来练。

## 七、主更新循环

**位置**：`source_training.py:598-771`

```python
for update in range(next_update, limit + 1):
    # ① 学习率调度：optimizer_rates(update-1) 写进三个 optimizer
    # ② world model 更新：model_batches 次 fit_model(window=8)
    # ③ critic + actor 更新：
    algorithm.improve_policy(policy_batch, critic_epochs, critic_minibatches,
                             update_actor=stage.actor_updates_enabled)   # warmup 阶段=False
```

- `update_actor` 开关是两个阶段的本质区别：warmup 期间只把 critic / world model 练到位，不动策略；
- 阶段切换（warmup → actor）触发整批重新采集并重建 replay。

## 八、评估与 checkpoint

**位置**：`source_training.py:658-712`

每到 `evaluation_interval`（或阶段末、最后一个 update）：

```python
evaluation = _evaluate(...)                        # root_xy_rmse_m 等指标
score = sum(所有 case 的 root_xy_rmse_m)
accepted = source_acceptance(evaluation, config)   # 验收门限
torch.save(payload, "latest.pt")                   # 每次评估都存
if accepted and score <= best_score:
    torch.save(payload, "best.pt")                 # 验收通过且创新低才存
```

无改进则 `patience += 1`。

## 九、停止条件与收尾

| 停止原因 | 位置 | 含义 |
|---|---|---|
| `success_patience_exhausted` | `source_training.py:706` | 连续 N 次评估无改进 |
| `max_environment_steps` | `source_training.py:713` | `TrainingBudget` 环境步预算耗尽 |
| `caller_update_limit` | `source_training.py:720` | `--max-updates` 冒烟限制 |

收尾（`source_training.py:727-762`）：

- 最后一个 update 即使不在评估边界也补发 `latest.pt`；
- 写 `stop_reason.json`，checkpoint 哈希回填 `identity.json`；
- 任何异常走 `:764` 兜底：只写 `failure.json`，**不发布**可能被误认成完成品的 checkpoint。
